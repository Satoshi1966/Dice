# DiceComp ― 6種類コンプリートゲーム

Java Servlet・JSPを使用した、6種類の出目をすべてそろえるWebアプリケーションです。キャラクター画像を使ったガチャ風の画面で、コンプリートまでの回数と合計を確認できます。

## ゲームのルール

- 「Lets,Gacha!!」ボタンを押すと、1～6のいずれかがランダムに出ます。
- 1回につき、合計に300が加算されます。実際の課金・決済機能はありません。
- 同じ出目が重複することがあります。
- 6種類すべてが一度以上出ると、コンプリートです。
- コンプリート後にもう一度ボタンを押すと、回数・合計・出目の状態が初期化されます。その次のクリックから新しいゲームが始まります。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| ランダム抽選 | `Math.random()`で1～6の出目を生成 |
| 画像表示 | 出目に対応するキャラクター画像を表示 |
| 進行状況の表示 | 未獲得の種類と、直近の出目を表示 |
| 回数・合計の表示 | 抽選回数と、回数×300の合計を表示 |
| 完了判定 | 全種類の獲得を判定し、メッセージを表示 |
| 状態の保持 | HTTPセッションでゲームの進行状況を保持 |

## 起動方法

1. JDK 17、Tomcat 9、Eclipseを用意します。
2. プロジェクトをダウンロードし、ZIPの場合は展開します。
3. Eclipseの「ファイル」→「インポート」から、既存プロジェクトとして取り込みます。
4. プロジェクトのJava実行環境をJava 17、ターゲット・ランタイムをTomcat 9に設定します。
5. Eclipseの「サーバー」ビューでTomcat 9を登録し、`DiceComp`を追加します。
6. Tomcatを起動し、ブラウザで次のURLを開きます。

```text
http://localhost:8080/DiceComp/Main
```

ポート番号やコンテキストルートを変更した場合は、URLも変更してください。`Main`の大文字・小文字にも注意してください。

`main.jsp`は`WEB-INF`配下にあるため、ブラウザから直接開かず、サーブレットの`/Main`へアクセスします。HTMLファイルのようにダブルクリックするだけでは実行できません。

## 遊び方

1. 初期画面に6種類の画像と「Push this Button」が表示されます。
2. 「Lets,Gacha!!」を押すと抽選が行われ、今回の出目が画面中央に表示されます。
3. `Count`で抽選回数、`Total`で合計を確認します。
4. 全種類をそろえると、`Complete! Try again!`が表示されます。
5. もう一度ボタンを押すと初期画面に戻ります。

表示例：

```text
Count:12 Total:3600 Complete! Try again!
```

この場合は、12回の抽選で全種類がそろい、合計は3,600です。

## プログラムの仕組み（MVC）

| 役割 | ファイル | 処理 |
| --- | --- | --- |
| Controller | `Main.java` | リクエストを受け取り、セッションから状態を取得して処理を呼び出し、JSPへフォワード |
| Model：データ | `Dice.java` | 出目の状態、抽選回数、合計、直近の出目、メッセージを保持 |
| Model：ロジック | `DiceLogic.java` | 抽選、回数・合計の更新、全種類の獲得判定 |
| View | `main.jsp` | 状態に合わせて画像、メッセージ、ボタンを表示 |

`Main.java`は、初回アクセス時に`Dice`を作成します。2回目以降のアクセスでは`DiceLogic.throwDice()`を実行し、結果をセッションの`dice`属性へ保存します。完了メッセージがある場合は、新しい`Dice`を作成して初期化します。

### 出目の状態管理

`diceStates`は6要素の配列で、添字0～5が出目1～6に対応します。

| 値 | 意味 |
| --- | --- |
| `0` | まだ一度も出ていない |
| `1` | 今回初めて出た |
| `2`以上 | 過去に出たことがある |

この配列は、出現回数そのものではなく、画像表示や獲得判定のための状態を表します。すべての要素が`0`以外になればコンプリートです。

## 動作上の注意

- 進行状況はセッション内に保持され、データベースやファイルへ永続保存されません。セッションの終了などで初期化されます。
- 抽選はGETリクエストで実行されるため、プレイ中にブラウザを更新しても抽選が進みます。完了直後の更新では初期化されます。
- フォームの送信先は`/DiceComp/Main`と記述されています。プロジェクト名・コンテキストルートを変える場合は、送信先も確認してください。
- JSPには`omikuji.mp3`を参照する記述がありますが、提示されたコードには自動再生や操作ボタンの指定がありません。

## 困ったとき

| 症状 | 確認すること |
| --- | --- |
| 404が表示される | Tomcatの起動状態、アプリの追加、URLの`/DiceComp/Main`を確認 |
| Servlet関連にコンパイルエラーが出る | プロジェクトのターゲット・ランタイムにTomcat 9が設定されているか確認 |
| 画像・CSSが表示されない | `webapp`配下の配置、ファイル名、大文字・小文字、参照パスを確認 |
| ボタンを押すと404になる | フォームの送信先と実際のコンテキストルートが一致しているか確認 |
